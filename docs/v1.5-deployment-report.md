# SwarmOS V1.5 生产部署报告

> 报告日期：2026-08-11（UTC）
> 目标环境：Ubuntu 虚拟机 `192.168.110.128`
> 部署目录：`/srv/projects/agent-os`

## 1. 当前结论

SwarmOS V1.5 的核心生产链路已经在目标虚拟机完成部署与实机验证。当前最终生产镜像为 `swarmos-app:v1.5.4`：控制面健康检查、就绪检查、生产冒烟测试均通过，Temporal Workflow/Activity Poller 已注册，正常 Run 与崩溃注入恢复场景均已完成生产验证。Completion Manifest HTTP API 保持 `200`；故障注入后连续观察 `2` 分钟未发现错误，`15` 分钟窗口内唯一错误为预期的 `CancelRun 409` 清理尝试。

本报告记录的是当前生产现场证据，不代表所有外围访问与 V2 能力均已验收完成。目前仍有以下明确边界：

1. Windows 宿主机直连 `192.168.110.128:8080` 仍受虚拟机 UFW 规则限制，需要用户在虚拟机控制台使用 `sudo` 放行端口后再做宿主机验收。
2. 生产故障注入 Case 15 只能标记为部分完成：cost ledger 与完整五类交叉演练尚未全部完成。

## 5. 网络结构与访问状态

部署过程中发现 Temporal 所在 Docker `internal` 网络会阻断所需的容器通信。现场修复方式是只让 Temporal 服务额外加入一个普通 bridge 网络，使应用容器能够访问 Temporal，同时保持端口暴露范围最小化。

当前网络约束：

- Temporal gRPC `7233` 仍只绑定宿主机回环地址 `127.0.0.1`，未向局域网公开。
- Web/HTTP 服务使用虚拟机端口 `8080`。
- 虚拟机内部健康检查、就绪检查和冒烟测试已经通过。
- Windows 宿主机当前尚不能直接访问 `192.168.110.128:8080`；原因是 UFW 放行规则尚待用户在虚拟机中使用 `sudo` 执行，因此不能把“Windows 直连”列为已通过。

UFW 放行后，宿主机验收地址应为：

- Console：`http://192.168.110.128:8080/`
- 健康检查：`http://192.168.110.128:8080/healthz`
- 就绪检查：`http://192.168.110.128:8080/readyz`

### 6.1 外围访问待验收

- **Windows 宿主机访问尚未验收**：UFW 端口规则需要用户在虚拟机控制台使用 `sudo` 执行，随后还需从 Windows 重新验证 Console、`/healthz` 和 `/readyz`。

### 6.2 已知 P1 能力边界

以下能力不属于本次已完成的 V1.5 核心生产闭环，仍需后续迭代或扩大故障注入覆盖：

- 通用 `INPUT → WAITING_USER` 的完整交互闭环。
- Agent/Model 自动切换，以及恢复阶段的自动 replan。
- 针对模型或外部服务 `429` 的完整自动故障转移。
- 真实 Git 高风险写操作适配器及其完整审批策略。
- 完整的多租户身份认证、授权与 RBAC 管理面。
- 生产设计中全部 15 类故障注入场景的逐项验收；其中 Case 15 当前仅部分通过，缺口是 cost ledger 和完整五类交叉演练。
- Temporal 当前负责 Run 级协调；Scheduler/Task 的部分执行链仍使用既有 NATS 路径，尚未全部迁入 Temporal。

这些边界不影响本次已验证的真实 Run 核心闭环，但在扩大生产流量、开放多租户或接入高风险外部工具前必须纳入发布门禁。

## 7. 灾难回滚要求

V1.5 已执行数据库迁移，因此发生严重故障时不能只切回旧镜像。灾难回滚必须同时恢复数据库，并接受恢复点之后新增数据会丢失这一事实。

建议的灾难回滚顺序：

1. 停止所有 Control Plane、Worker、Workflow Worker 及其他数据库写入者。
2. 保存当前故障现场的日志、容器状态和数据库快照，避免覆盖诊断证据。
3. 校验备份文件大小及 SHA-256 与本报告记录一致。
4. 使用 `swarmos-final-pre-v15.dump` 恢复正式切换前的数据库状态。
5. 恢复与该数据库状态匹配的旧版运行时和配置。
6. 先完成数据库一致性检查，再启动写入流量。
7. 重新执行健康、就绪和核心业务冒烟测试。

除非已经完成向后兼容性验证，否则禁止采用“仅回滚应用容器、保留迁移后数据库”的方式处理生产故障。
